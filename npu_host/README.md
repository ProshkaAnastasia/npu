# Python-клиент нейросетевого процессора

Python 3.10+; одна зависимость — pyserial 3.5. Клиент соответствует последним `io_types_pkg`, `io_controller`, `sequencer` и `nn_processor_top` из нашего проекта. RTL должен поддерживать команды 01–08. Параметры памяти и формата соответствуют значениям по умолчанию: shared memory 16 KiB, RESULT_RECORD=0x3200, до 8 слоёв, до 49 нейронов. При изменении этих параметров нужно согласовать проверки в клиенте.

## Установка и первый запуск

Распакуйте архив, откройте терминал в его папке:

```sh
python -m pip install -r requirements.txt
python npu_uart.py --list-ports
python npu_uart.py --port COM3 --baud 115200 --model examples/model.bin --input examples/input.json --output result.json --verbose
```

Замените COM3 своим портом. В Linux можно использовать `/dev/ttyUSB0` или `/dev/ttyACM0`. Параметры линии: 8N1, без аппаратного и программного flow control. Baud rate должен совпадать с UART_BAUD_RATE аппаратного верхнего модуля; 12.5 Mbaud из testbench — только ускорение симуляции, по умолчанию аппаратный модуль использует 115200.

Программа требует настоящего UART-подключения к работающему процессору. Behavioral Simulation в Vivado сама по себе не создаёт COM-порт. Плату нужно предварительно запрограммировать; загрузка конфигурации сети по UART не загружает bitstream FPGA.

Перед первым подключением к новому сеансу обеспечьте, что процессор не занят незавершённой старой командой; после аварийного обрыва обмена может потребоваться его reset. Сам клиент не управляет reset FPGA. Не открывайте тот же COM-порт одновременно в другой программе.

## Какие файлы передавать

- `examples/model.bin` — готовый бинарный NNP2-образ той же сети 49→12→3, которая прошла testbench.
- `examples/input.json` — JSON-массив из 49 чисел.
- `examples/expected.json` — ожидаемый результат этой сети для 6 PE.
- `examples/test_model.mem` и `examples/test_input.mem` — те же данные в формате hex из симуляции.

Вместо `.bin` можно передать модель `.mem`:

```sh
python npu_uart.py --port COM3 --model examples/test_model.mem --input examples/test_input.mem
```

Для входов также поддерживаются обычный текст с числами через пробелы/запятые/переносы строк и бинарный little-endian FP32 `.bin`. JSON должен содержать один плоский массив чисел, например `[0, 1, 0, 0.5]` для модели с четырьмя входами. Количество значений должно совпадать с моделью. Этот клиент передаёт готовый NNP2-образ, а не преобразует произвольный файл PyTorch/ONNX/JSON в NNP2.

`.mem` содержит 32-битные hex-слова через пробелы или переводы строк, без `32'h`, адресов `@` и маркеров `x/z`. При загрузке каждое слово преобразуется в четыре байта little-endian.

## Порядок обмена

1. Проверяется формат NNP2, размеры и CRC образа на компьютере.
2. CONFIG_BEGIN передаёт размер образа.
3. CONFIG_DATA передаёт части до 256 байт; каждая часть сопровождается смещением.
4. CONFIG_END ждёт проверки модели и распределения весов по PE.
5. INPUT_BEGIN / INPUT_DATA / INPUT_END передают входной вектор FP32.
6. RUN запускает вычисление и ждёт ответа с адресом результата.
7. READ_WORD читает служебную запись и все выходы сети. Клиент проверяет число выходов, адрес, статус и argmax.

Ответы проверяются по CRC, CMD и SEQ. Значение поля next_offset трактуется согласно команде. В JSON результата выводятся `class_index` (индекс от нуля), `output_address`, массив `outputs` и точные битовые представления `output_hex`. Выход sigmoid не является softmax: сумма выходов не обязана быть равна единице.

На stdout записывается только JSON результата, сообщения о ходе работы — на stderr. `--output result.json` дополнительно сохраняет результат в файл. По умолчанию модель загружается при каждом CLI-запуске.

## Повторные входы без загрузки весов

```python
import serial
from npu_uart import Model, NpuClient

model = Model.load("examples/model.bin")

with serial.Serial(
    "COM3", baudrate=115200,
    bytesize=8, parity="N", stopbits=1,
    timeout=0.05, write_timeout=5,
    xonxoff=False, rtscts=False, dsrdtr=False,
) as port:
    client = NpuClient(port)
    client.upload_model(model)

    # В каждом infer передаётся новый вход; веса остаются в PE.
    first = client.infer([0.0] * model.input_count)
    second = client.infer([1.0] * model.input_count)
    print(first)
    print(second)
```

Клиент не предназначен для одновременных вызовов из разных потоков. При использовании класса самостоятельно задавайте короткий read timeout порта (например, 0.05 s), чтобы действовали сроки ожидания ответа.

## CRC, повторы и тайм-ауты

Кадр: `A5 5A | CMD:8 | SEQ:16 | LEN:16 | payload | CRC32:32`. Многобайтные поля little-endian. CRC-32/ISO-HDLC по CMD+SEQ+LEN+payload; `zlib.crc32` соответствует RTL. Не нужно дополнительно XOR-ить результат zlib с 0xFFFFFFFF.

По умолчанию клиент ждёт обычную команду 5 s, RUN — 30 s, делает до двух повторов. Можно указать `--timeout 10 --run-timeout 60 --retries 2 --chunk-size 128`. Размер части — кратное 4, от 4 до 256.

При потере/повреждении ответа повторяется **весь тот же пакет с тем же SEQ**, включая RUN. Последний ответ кэшируется в IO, поэтому потеря ACK не приводит к повторному вычислению. Анонимные ошибки транспортного уровня CRC/format/timeout тоже допускают повтор. Прикладные ошибки устройства, включая MODEL_CRC, BAD_STATE, PE_ERROR, не повторяются автоматически: программа сообщает их и останавливается.

Для SEQ выбирается случайное начальное 16-битное значение, затем счётчик увеличивается с переполнением. Это уменьшает вероятность совпадения с последним запросом прошлого сеанса, но не заменяет восстановление состояния устройства после обрыва связи. При SEQ_ERROR программа останавливается, а не меняет номер автоматически.

Если повторы исчерпаны, нельзя считать, что операция не выполнилась. Клиент блокирует дальнейшие команды этого экземпляра. Не запускайте новый RUN автоматически: восстановите соединение и известное состояние процессора. Тайм-аут компьютера не отменяет операцию в FPGA. Не выбирайте короткий тайм-аут для штатно долгих операций; пакет, переданный занятому IO, может быть проигнорирован.

При неполной записи кадра/ошибке serial клиент также прерывает сеанс: безопасная граница пакета неизвестна. Прикладную ошибку записи части он не пытается автоматически исправлять новым SEQ.

## Проверка без платы

```sh
python -m unittest -v test_npu_uart.py
```

Проведено 10 автоматических тестов на эмуляторе протокола: полный цикл загрузки/вычисления/чтения, несколько входов без перезагрузки весов, потеря ACK RUN с единственным выполнением RUN, CRC ответа, транспортная ошибка, фрагментация ответа, устаревший ответ, переполнение SEQ, прикладная ошибка, тайм-аут, неполная запись и проверка файлов/входов. Проверен CRC контрольной строки `123456789` = 0xCBF43926.

Эмулятор возвращает эталонные результаты; он не вычисляет нейросеть и не заменяет проверку вычислений. Сам Python-клиент на физической плате не запускался. Предыдущие тесты RTL в Vivado с настоящими моделями Floating-Point IP прошли, но соединение именно этого Python-клиента с платой ещё нужно проверить.
